What It Does

Everything a supermarket needs in one platform

Built to solve real operational problems in Ethiopian retail — from checkout to stock management to financial reporting.

🛒

Point of Sale

Barcode scanning, cart management, promo codes, multiple payment methods (cash, card, mobile), and thermal receipt printing. Works offline on Windows via the desktop app.

Real-time stock deduction
📦

Multi-Location Inventory

Track stock across warehouses, shelves, and store rooms. The POS automatically filters to show only shelf-ready stock. Location-branch validation enforced on every write.

Shelf vs warehouse separation
⚡

Real-Time Stock Sync

When any cashier completes a sale, all connected POS terminals instantly update via WebSocket. No overselling. Missed events are replayed when a terminal reconnects.

WebSocket + event replay
💻

Offline Desktop POS

A native Windows application (Tauri + Rust) that stores sales in local SQLite when offline. Automatically syncs to the server when connectivity is restored using idempotency keys.

Tauri + Rust + SQLite
📊

Deep Analytics

Dashboard KPIs, 30-day revenue trends, profit and loss reports, top products, employee performance, dead stock alerts, and hourly sales heatmaps. All exportable to CSV.

11 report types
🏢

Multi-Tenant SaaS

Multiple independent supermarket businesses on one deployment. Complete data isolation at the query level — one tenant can never see another's data, enforced on every API call.

Shared-DB tenant isolation
🔄

Full Operations Suite

Purchase orders with partial receives, sales returns with over-return prevention, physical stock takes with discrepancy tracking, and shift management with atomic totals.

ACID transactions throughout
👥

Role-Based Access Control

Five user roles — Platform Admin, Super Admin, Branch Admin, Cashier, Inventory Manager. Branch-level isolation: cashiers can only see and sell their own branch's products.

Configurable per tenant
📋

Immutable Audit Log

Every significant action — sales, stock adjustments, user changes — is recorded with a user identity snapshot. The log is read-only, ordered newest first, and filterable by entity type.

Tamper-evident trail

Security Engineering

4 real vulnerabilities found and fixed through TDD

The 260-test automated suite was designed adversarially — tests that attempt to violate security boundaries caught real bugs before deployment.

✓

Logout token invalidation

Access token remained valid after logout until JWT expiry. Fixed with an in-memory blocklist.

✓

Cross-branch sale exploit

Cashier from Branch B could sell Branch A's products by supplying the product ID directly.

✓

Cross-branch location assignment

Products could be assigned locations from other branches, causing them to disappear from the POS silently.

✓

Hourly heatmap SQL error

GROUP BY EXTRACT() syntax rejected by PostgreSQL (code 42803), causing 500 errors on the reports page.
